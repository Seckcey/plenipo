# v1.14.2 — Connections: HubSpot, Stripe, your website, and add-on tools (Phase 20, part 20C)

Workers can now use **HubSpot**, **Stripe**, and a **WordPress** site with its **WooCommerce**
store, on the same rules as Microsoft 365, Slack, and Google. Each connects with a key made in the
service and typed into its card in Settings; the key goes only to Windows Credential Manager and is
never shown again. **Add-on tools** let other programs that offer tools join in, each tool off
until approved.

This is the last of three parts of Phase 20: **Connections are complete**. Nothing relied on
before changed how it works.

## Highlights

- **Keys, typed into the card.** HubSpot takes a **service key**, Stripe a **restricted key**
  (test mode first), and the website its address, a WordPress user name, and an **Application
  Password** (a WooCommerce key is optional). **Save and check** tries the key with one reading
  call and keeps it only if the service accepts it. **Replace the key** swaps it for the same
  account. Steps, click by click:
  [Making keys for HubSpot, Stripe, and your website](https://github.com/Seckcey/plenipo/blob/main/docs/phases/phase-20-keys-for-hubspot-stripe-and-website.md).
- **HubSpot's parts:** **Contacts**, **Companies**, and **Deals** — search and read each, with its
  latest notes; Full access adds creating or changing one, and adding a note. No emails,
  sequences, or deleting. 12 tools.
- **Stripe's parts:** **Payments** (the balance, payments, and payouts; Full access adds
  **refunds**), **Customers** (read only), and **Invoices** (invoices and subscriptions; Full
  access adds **drafting** an invoice, and **finalizing and sending** one). No charges, payouts, or
  payment links. 11 tools.
- **Your website's parts:** **Posts and pages** (read them and their comments; Full access adds
  drafts, **publishing**, and **changing what is published**) and **Store** (orders and their
  notes, products, and customers; Full access adds private order notes, an order's status, notes
  the customer sees, and **refunds**). 13 tools.
- **Add-on tools.** Under **Add-on tools**, **Add a program** installed on this PC that offers
  tools. It starts **off**. Switching it on lists its tools, each **Off** until marked **Reading**
  (goes ahead) or **Changing** (asks every time). Only the stored secrets named for it reach it,
  and nobody may use it until **Who may use it** says so.
- **36 new connection tools** (and each add-on's own) for Claude Code, Codex, Grok, and Kimi
  workers.

## Safer than before

- **Money always asks — no exceptions.** A Stripe refund, finalizing and sending a Stripe
  invoice, and a store refund each wait for approval every time, whatever the switches and lists
  say. The card shows the **amount**, the **currency**, the **customer**, and **Test mode** or
  **LIVE MODE**. Just before acting, Plenipo reads the payment, invoice, or order again and stops
  if any of those changed. Stripe requests carry a one-time key, so a retry never pays twice; a
  store refund is never retried.
- **Stripe asks again.** With a key tagged for an agent (the steps say how), Stripe also holds each
  refund for approval in its own Dashboard.
- **Publishing asks, every time.** Publishing a post, or changing anything already published,
  reaches everyone who visits the site, so no list can let it go ahead without asking.
- **Other people's words stay information.** A HubSpot note, a Stripe payment's description, a
  WordPress comment, a WooCommerce order note, and an add-on's answer reach workers marked as
  information, never instructions. Planted "ignore your instructions and …" text in each was
  tested, and obeyed in none.
- **The website password goes to one place.** The website connection reaches only the exact
  address saved on its card, over https; a redirect anywhere else — even to `www.` — is refused.
- **Keys stay in the Vault.** Never in the Ledger, a worker's instructions, a log, or the
  diagnostics file — even a key the service refused. **Disconnect** removes every key, and revokes
  the website's Application Password at the site.
- **The record keeps no copies.** IDs, links, amounts, and short summaries only: an approval card
  shows a payment's description, an invoice's lines, or a post's words so they can be checked,
  and the record keeps "(not kept)" in their place.
- **Add-ons stay in their lane.** Programs that download code each time they start (`npx`,
  `uvx`, `bunx`, and the like) and shells are refused. A tool whose description or input changes
  goes back to **Off** until looked at again. An add-on runs only for a worker's step, and is
  stopped after.

## Decisions

- [ADR-071 (HubSpot, Stripe, the website, and add-on tools: the choices, and what the services' pages changed)](https://github.com/Seckcey/plenipo/blob/main/docs/adr/ADR-071-keys-website-and-add-on-choices.md)
  — **accepted**, every choice as recommended: keys typed into Settings (a Stripe key tagged for an
  agent); downloading programs refused; nobody may use a new connection or add-on until picked,
  each line starting at Read only; the website reached only at its saved address; a store refund
  sends the money back through the store's payment company.

## Upgrading from 1.14.1

Run the 1.14.2 installer, or choose **Install now** when Plenipo offers the update. The Ledger's
layout does not change (it stays at layout 11), and it is backed up first, as always. Microsoft
365, Slack, and Google connections and settings carry over.

## Known limits and risks

- **HubSpot's service keys are a public beta.** HubSpot may change them. A key from an existing
  private app works too; HubSpot stops new private apps on 2026-10-26.
- **Stripe live keys move real money.** Start with a test-mode key. Stripe's terms say what an AI
  agent does through the account is binding.
- **An Application Password has its WordPress user's full permissions.** Make a user just for
  Plenipo (Editor, or Shop Manager for the store), never an Administrator.
- **A site that moves visitors between `example.com` and `www.example.com`** must be saved under
  the address it ends at.
- **Add-on programs run with the full account, like any approved program.** Add only programs
  from a publisher that is trusted — ideally the service's own.
- **Not yet checked with real HubSpot, Stripe, or WordPress accounts.** CI uses stand-ins. Still to
  try on Windows: make each key, connect, let a worker read and draft, approve a test-mode Stripe
  refund, publish a draft, add an add-on program, and disconnect.
- **Client data goes to the AI company.** What a worker reads (a contact, an order, a payment) is
  sent to the AI tool it runs on. Check agreements with clients first.
- **Selling Plenipo Pro with these connections** may need its terms reviewed by a lawyer.
