# v1.9.0 — Installs, updates, and recovers cleanly (Phase 13)

Plenipo now behaves like dependable Windows software. Closing the window keeps your work going in
the tray. Opening Plenipo again shows the one already running. If Plenipo or Windows stops
unexpectedly, the next start tells you what happened and what stopped, and nothing runs again
until you say so. The Ledger is backed up every day and before every new version. Plenipo tells
you when a new version is out, and installs it only when you say so, and only if 8 West signed it.

Nothing you rely on changed how it works. Your organization, projects, workers, approvals,
permissions, servers, switches, and terminal are where you left them.

## Highlights

- **Plenipo lives in the tray.** Closing the window hides it while work is going, and the work
  goes on. Settings → **Start and close** lets you choose:
  - **Keep Plenipo in the tray while work is going** (the starting choice): with nothing going,
    closing quits.
  - **Always keep Plenipo in the tray**: closing only hides the window; quit from the tray menu.
  - **Quit Plenipo and stop its work**: closing is the same as Quit.
- **Start Plenipo with Windows** (Settings → Start and close, **off** until you turn it on). It
  starts in the tray, with no window, when you sign in. Windows' own Settings → Apps → Startup
  can turn it off too.
- **Only one Plenipo.** Opening Plenipo again (from the Start menu, a shortcut, or Windows
  starting it) shows the window of the one already running.
- **If the window stops responding**, Plenipo reloads it, and if that does not help, closes it and
  opens a new one. Your work keeps running; the window says it was brought back.
- **After an unexpected stop**, the next start says what happened, in plain words, above the page:
  - **Plenipo closed unexpectedly** (it crashed, or was ended from Task Manager);
  - **Windows restarted while Plenipo was running** (or the computer lost power);
  - **Plenipo was stopped while updating the Ledger**: nothing is lost; the unfinished step is
    undone and done again, with a backup from before it;
  - and, as before, when an AI tool stops unexpectedly, only its own task stops: the
    conversation says **AI tool stopped unexpectedly**, the task shows in **What's stuck** on
    Home, and Plenipo keeps running.

  It lists the tasks that stopped, each with **Run again** (a new task with the same request, for
  the same worker) or **Leave stopped**. Nothing runs again by itself. A pop-up notice says so too
  (Settings → Notifications → **Plenipo itself**).

- **Backups of the Ledger, on a schedule** (Diagnostics → **Backups of the Ledger**): one every day
  while Plenipo runs (a week kept, made when no work is going), one before a new version first uses
  the Ledger, one before installing an update, and yours from **Create backup**. Each shows when
  and why it was made.
- **Restore** a backup from Diagnostics: choose **Restore**, then **Restore and restart**. Plenipo
  checks the backup first, keeps the Ledger as it was (as a backup, "Before a restore"), and
  restores when it starts again. A damaged backup, or one from a newer Plenipo, is refused and
  your Ledger is left alone.
- **Settings Plenipo could not read** are named above the page, with **Restore a backup** or
  **Reset to starting settings** (a backup is made first).
- **Log files.** Plenipo writes what it does to `logs\plenipo.log` in its folder, starts a new
  file at 2 MB, and keeps five. Secrets, and what you type in the terminal, are never written.
- **Save a diagnostics file** (Diagnostics, and Settings → Diagnostics): one file to send when
  something went wrong. It holds this version, Windows, the Ledger's health and backups, how the
  last run ended, the AI tools found, recent event types, and the log files. No tasks, no answers,
  nothing you typed in the terminal, and no secrets. **Copy its location** to find it.
- **Updates** (Settings → **Updates**, and **Update ready** in the top bar when there is one).
  Plenipo checks GitHub a few minutes after it starts, then once a day, for Free and Pro alike. The
  check sends nothing about you or your work. You see what is new, and choose **Install now**.
  Plenipo then downloads it, checks that 8 West signed it for that version, backs up the Ledger,
  stops the work (it asks first if work is going), and hands over to the installer, which opens
  Plenipo again. If anything goes wrong before the installer starts, this version keeps running.
- **The installer and uninstaller**, in plain words:
  - Installing over a running Plenipo asks it to stop its work and quit the normal way first.
  - Uninstalling **keeps your data** (the Ledger, its backups, and settings) unless you tick
    **Also delete my Plenipo data**, which also removes the secrets Plenipo kept in Windows
    Credential Manager. Start with Windows is always removed.
- **Your version** is in the top bar and in Settings → About Plenipo, as before, and in Settings →
  Updates.

## Decisions

- [ADR-036: background work](https://github.com/Seckcey/plenipo/blob/main/docs/adr/ADR-036-background-work.md)
  — **accepted** by you, and built in this release. Accepting it means the work stays in the one
  Plenipo program that lives in the tray, not in a separate Windows service; the window can come
  and go without stopping it; and nothing restarts by itself after a crash (you choose Run again).
- [ADR-037: updates](https://github.com/Seckcey/plenipo/blob/main/docs/adr/ADR-037-updates.md) —
  **accepted** by you, with your choice: checking is always on, for Free and Pro, with no switch
  to turn it off. Installing still happens only when you choose Install now, and only a version
  signed with 8 West's updater key.

## Free and Pro

Checking for updates is the same for Free and Pro, and separate from any license check. It reads a
public file from Plenipo's GitHub Releases; GitHub sees what any website sees (your internet
address, and that a copy of Plenipo asked). It never sends your projects, tasks, or anything from
the Ledger. Someone who wants no internet traffic at all can block it with a firewall: Plenipo
then says it could not check, and keeps working.

## Upgrading from 1.8.0

Run the 1.9.0 installer. No Ledger migration. The first time 1.9.0 opens your Ledger, it backs it
up first ("Before a new version (from an earlier one)", in Diagnostics). Close to the tray and
Start with Windows start the way you would expect: the window hides while work is going, and Start
with Windows is off.

**This is the last version you install by hand.** From 1.9.0, Plenipo finds the next version for
you. (Once, before the first update-ready release, 8 West adds its updater key to GitHub; see
[ADR-037, section 6](https://github.com/Seckcey/plenipo/blob/main/docs/adr/ADR-037-updates.md#6-what-the-owner-does-once-the-updater-key).)

**Going back to 1.8.0**, if you ever need to: run the 1.8.0 installer from
[GitHub Releases](https://github.com/Seckcey/plenipo/releases). Your Ledger and settings are kept
(1.9.0 does not change the Ledger's layout), and Diagnostics can restore the backup made before an
update.

## Known limits and risks

- **Not yet checked on Windows by you.** On GitHub's Windows machine, the tests install this
  version silently, run it, end it the hard way (a crash, a simulated Windows restart, a crashed
  window), upgrade over 1.8.0, go back to 1.8.0 and forward, install an update the way Plenipo
  does, uninstall, and list what is left behind (nothing). Please check on your PC: a fresh
  install, an upgrade from 1.8.0, an uninstall, a real restart of Windows with work running, and
  an update (from the first release after this one).
- **Installing an update stops running work.** The new program replaces the one doing the work,
  so Plenipo asks first and records what it stopped; Run again starts it again.
- **If the installer itself fails halfway** (rare), the old version may not open. Run the
  installer again, or the older one from GitHub Releases; your data is not in the program folder,
  so it is safe either way.
- **The updater key.** If 8 West loses it, copies already installed refuse updates signed with a
  new one, and everyone installs the next version by hand once.
- **Terminals do not survive the window being reopened**: a crashed window closes the terminals
  open in it (the window says so). Workers' server commands are not affected.
- Earlier checks still to do on Windows: the Phase 11 check against a real server
  ([Phase 11 checklist](https://github.com/Seckcey/plenipo/blob/main/docs/phases/phase-11-checklist.md)),
  and Phase 12's real notices and the terminal with PowerShell and a real server
  ([Phase 12 report](https://github.com/Seckcey/plenipo/blob/main/docs/phases/phase-12-acceptance-report.md)).

## Install

Download `Plenipo_1.9.0_x64-setup.exe` below and run it. It is a per-user install with no admin
rights needed, signed as **8 West Ventures, LLC**. If SmartScreen still warns, choose **More info →
Run anyway**.
