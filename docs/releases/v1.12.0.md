# v1.12.0 — The AI tools page: sign-in, usage, and updates (Phase 19)

Everything about each AI tool is now in one place, on the **AI tools** page. Sign in, reconnect,
or sign out without leaving Plenipo. See how much each model has been used this week, the usage
limit and when it resets, and — for Claude Code and Codex — how much of your plan is left. See
how each tool is paid for. Keep each tool up to date: Plenipo looks for new versions once a day
and updates a tool only when no task is using it. And see each tool's models, with new ones
marked **new — not checked yet**.

Nothing you rely on changed how it works. Your organization, projects, workers, approvals,
permissions, servers, switches, and terminal are where you left them.

## Highlights

- **Sign in, Reconnect, Sign out** on each AI tool's card. The button opens a tab in the terminal
  panel that runs that tool's own sign-in program — for example `codex login` — and nothing
  else. You sign in there, and in your browser, exactly as you would in PowerShell. Plenipo never
  sees, keeps, or passes your sign-in, never types into the tab, and never opens the files where
  an AI tool keeps it. When the program ends, Plenipo checks the tool again by itself and the
  card shows the new state. Kimi has no sign-out command, so its card has no Sign out button.
- **Signing out waits for tasks.** While a task is using a tool, Sign out and Reconnect wait
  ("Waiting: 1 task is using Codex") and open the tab when it finishes — even if you look at
  another page meanwhile — or you press **Cancel**. While a sign-in program runs, new tasks on
  that tool wait for it (ten minutes at most, so a tab left open never stops your work).
- **Usage.** Each card's **Usage** tab adds up the tokens (pieces of words) each model read and
  wrote — today, this week (Monday to Sunday), last week, and each of the last 14 days — from the
  counts Plenipo already saved with every task. Kimi does not report token counts, so its card
  counts tasks.
- **The usage limit, and what is left of your plan.** The usage limit and its reset time moved
  here from Settings → AI models, with **Try again now**. Claude Code reports how much of your
  plan is used in the messages Plenipo already reads during a task, and Codex through its
  official app server; the card shows it with the time it was reported. Grok, Kimi, and Ollama
  do not report it, and their cards say so.
- **How it is paid for:** **Subscription**. The switch to a paid AI key is shown, but it cannot be
  turned on until spending caps exist (Phase 16).
- **Versions and updates.** Each card shows the version you have and the version Plenipo was
  tested with, and says so when they differ. Once a day, Plenipo looks for a new version: Grok's
  own check, and the release lists Anthropic and OpenAI publish on npm and Ollama publishes on
  GitHub (read-only, through Guard; nothing about you is sent). **Update** runs the tool's own
  official update command — only when no task is using the tool; if one is, it waits. Then
  Plenipo checks the version, the sign-in, that the tool still answers the way Plenipo reads it,
  and its models. A new task on a tool that is updating says "Waiting: Grok is being updated"
  and starts when that's done; **Stop** works while it waits. An update and a sign-in tab never
  run on one tool at the same time.
- **Update AI tools by themselves** — a new switch, on the AI tools page and in Settings →
  Switches, **off** by default. Off, Plenipo only tells you (the card and a Windows notice). On,
  it updates each tool by itself, the same way, when no task is using it — and still tells you
  about what it cannot update: Ollama's new versions, and a tool installed with npm or WinGet,
  whose command it tells you once.
- **A failed update leaves the old version working,** and the card says so. If a new version does
  not answer the way Plenipo reads it, Plenipo puts the old one back with the tool's own command
  (Claude Code and Grok have one); otherwise it stops giving that tool tasks and tells you how to
  install it again.
- **Ollama** has no update command: its own tray app downloads new versions and asks you to
  restart it. The card shows Ollama's version and the newest one. **Kimi** publishes no version
  list that matches its program, so **Update** asks Kimi to check and install a new version if
  there is one.
- **Models.** Each card's **Models** tab lists the models Plenipo checked and the ones the tool
  reports itself: Codex through its app server, Grok and Kimi through ACP, Ollama from its
  service. A model Plenipo has not checked is marked **new — not checked yet** and can still be
  chosen in every model menu. Claude Code has no list of its own; its models come with Plenipo's
  updates.

## Safer than before

- **Codex no longer looks for its own updates during a task.** Claude Code's and Grok's
  self-updaters were already off; Plenipo now switches off Codex's too, and updates each tool
  only between tasks.
- **A sign-in tab gets only what the tool's tasks get.** It runs the tool's program directly, with
  no shell in between, and with the same short list of settings as its tasks — so an API key set
  on your PC never reaches it.

## Decisions

- [ADR-058: signing in to an AI tool in a terminal tab](https://github.com/Seckcey/plenipo/blob/main/docs/adr/ADR-058-signing-in-to-ai-tools-in-the-terminal.md)
  — **accepted** by you, as recommended. Accepting it means sign-in happens only in a tab that
  runs the tool's own sign-in program, Sign out and Reconnect wait for tasks, and Kimi has no
  Sign out button.
- [ADR-059: Plenipo keeps the AI tools up to date, between tasks](https://github.com/Seckcey/plenipo/blob/main/docs/adr/ADR-059-plenipo-updates-the-ai-tools.md)
  — **accepted**, as recommended. Accepting it means Plenipo runs each tool's own update command
  only when no task uses it, asks first unless you turn on the switch, puts the old version back
  with the tool's own command where there is one, and leaves Ollama's updates to its tray app.
- [ADR-060: usage, "plan left", and new models](https://github.com/Seckcey/plenipo/blob/main/docs/adr/ADR-060-usage-plan-left-and-new-models.md)
  — **accepted**, as recommended. Accepting it means usage is added up from what Plenipo already
  saved, "plan left" comes only from Claude Code's task messages and Codex's app server, and new
  models are marked and can be chosen.

## Upgrading from 1.11.0

Run the 1.12.0 installer, or choose **Install now** when Plenipo offers the update. The Ledger's
layout does not change (it stays at layout 11), and it is backed up first ("Before a new
version"), as always. Your organization, work, and settings carry over.

## Known limits and risks

- **Not yet checked on Windows by you.** Please try: sign Codex out and back in from its card;
  look at this week's usage for Claude Code by model; update Grok with one click (or turn on the
  switch and let it update by itself) while no task uses it, and see a model that arrived with
  the update marked as new.
- **Checks on your real AI tools:** whether `codex update` updates a Codex installed with npm (if
  not, the card shows the npm command to type); that `grok update` works with Grok's own
  self-updater switched off; whether Kimi updates itself during a task; whether Claude Code
  reports the share of your plan used; and that Codex's app server answers for your plan and
  models.
- **"Plan left" for Claude Code is as fresh as its last task.** The card says when it was
  reported.
- **Asking Kimi for its models leaves an empty conversation in Kimi's own history,** so Plenipo
  asks only after an update and when you press Check again.
- **Updates happen only while Plenipo runs** (it lives in the tray).
- **While one AI tool updates,** tasks waiting for it count toward the tasks Plenipo runs at
  once, so for those few minutes fewer tasks can start on your other AI tools.
- **Sign out does not wait for a task that is between steps** (for example, waiting for another
  worker's reply); its next step then asks you to sign in again.

Download `Plenipo_1.12.0_x64-setup.exe` below and run it, or let Plenipo install the update. It is
