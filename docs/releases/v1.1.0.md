# v1.1.0 — Grok joins the AI tools

Plenipo can now run tasks on **Grok (xAI)**, next to Claude Code and Codex. Sign in to Grok once
with your grok.com subscription (`grok login`), and Plenipo shows it under **AI tools** and offers
its models wherever you pick a model.

## Highlights

- **Grok as an AI tool.** Pick **Grok** in **Workers**, for a Supervisor, or in a role's model
  choices. Plenipo checks the sign-in the same way it does for Claude Code and Codex: the
  **AI tools** card says **Ready** with "grok.com sign-in", or **Not signed in** with the hint to
  run `grok login`.
- **Grok's models.** `grok-4.7` (Grok's default), `grok-4.7-build-fast` ("Grok 4.7 Fast"), and
  `grok-4.6` take Low to Extra high effort; `grok-4.5` takes Low to High. Find them under
  **Settings → AI models → Add a model**.
- **Plenipo's tools, not Grok's own.** In a project, Grok reads files, lists folders, and runs
  commands only through Plenipo's tools, so the Guard's permissions and approvals apply to Grok
  exactly as they do to the other AI tools. Grok's own shell, file editing, web search, X search,
  subagents, and memory are turned off.
- **Subscription only.** Plenipo tells Grok to refuse API keys, including one set on a model in
  Grok's own settings, so tasks always run on your grok.com sign-in.
- **Follow-ups and Cancel.** A follow-up continues the same Grok conversation. **Cancel** asks
  Grok to stop and ends it after five seconds if it hasn't.

## Before you start

- Install Grok 1.0.41 or newer (`irm https://x.ai/cli/install.ps1 | iex`), then `grok login`.
  Keep it up to date with `grok update`.
- A project made before this release does not allow Grok yet: **Edit project**, tick **Grok**
  under **Allowed AI tools**, and save.

## Under the hood

- Plenipo talks to Grok over ACP (the Agent Client Protocol), under ADR-015 (running AI tools
  over ACP). The prompt goes in on standard input, never on the command line.
- One shared ACP driver, so later AI tools that speak ACP need only a small adapter.
