# v1.5.0 — Kimi joins the AI tools

Plenipo can now run tasks on **Kimi**, Moonshot AI's Kimi Code, next to Claude Code, Codex, Grok,
and Ollama. It uses your own Kimi subscription sign-in, never an API key. Kimi's own tools cannot
be switched off, so Plenipo handles every file Kimi reads or writes itself, through Guard.

## Highlights

- **Kimi as an AI tool.** Install Kimi Code, run `kimi login` once, and the **AI tools** card says
  **Ready** with "Kimi sign-in". Pick **Kimi** in **Workers**, for a position, or in a role's
  model choices.
- **Every file goes through Plenipo.** Kimi asks Plenipo for each file it reads or writes, and
  Guard decides, just as for Plenipo's own file tools:
  - only inside the project folder, and never a file you blocked;
  - secrets are hidden in what Kimi reads;
  - every read and write is recorded, and waits for your approval where you asked for it.

  A worker without permissions gets no files at all.

- **No command line of its own.** Kimi's own shell is always refused. Workers run programs with
  Plenipo's `run_command`, under your command rules. Plenipo approves each request once, never
  "for this session".
- **Safe modes only.** Kimi runs in its **default** mode, where it asks before acting, or in
  **plan** (read-only) for a worker without permissions. It never runs in **auto** or **yolo**;
  if it switches itself, Plenipo stops the task.
- **Your subscription's models.**

  | Model                                 | Name in Kimi        | Thinking           |
  | ------------------------------------- | ------------------- | ------------------ |
  | `kimi-code/k3` (Kimi's default)       | K3                  | low, high, or max  |
  | `kimi-code/k3-256k`                   | K3-256k             | Kimi's own default |
  | `kimi-code/kimi-for-coding`           | K2.8 Preview        | Kimi's own default |
  | `kimi-code/kimi-for-coding-highspeed` | K2.7 Code Highspeed | low                |

  Only these subscription models run. Plenipo always names one (K3 when you choose none), so a
  different default in Kimi's own settings is never used.

- **Like every AI tool:** follow-ups remember the conversation, **Cancel** stops a task within
  seconds, and every step is in the Activity trail.

## Before you start

- Install Kimi Code with its official installer (see moonshotai.github.io/kimi-code). On Windows it
  puts `kimi.exe` in `%USERPROFILE%\.kimi-code\bin`.
- Run `kimi login` and sign in with the Kimi account that has your subscription.
- To check the sign-in yourself, run `kimi provider list`. It should show
  `managed:kimi-code … source=oauth`.
- A project made before this release does not allow Kimi yet. Choose **Edit project** and tick
  **Kimi** under **Allowed AI tools**.

## Known limits

- Kimi reports no token counts, so its tasks show none.
- Kimi's own short file paths start from its conversation folder, outside your project, so Guard
  refuses them. Kimi then uses full paths or Plenipo's file tools.
- Kimi still loads your own Kimi settings, such as skills you installed and `AGENTS.md` files. The
  files it reads for them go through Plenipo too, so the folder rules still apply.
- Checked with Kimi Code 0.34.0. Each new Kimi version needs a new check.

## Under the hood

- Plenipo runs `kimi acp`, one program per task, and talks to it over ACP through the same driver
  as Grok. Its mode, model, and thinking level are set at the start of each task and checked.
- Kimi's file requests use the same Guard path as Plenipo's `read_file` and `write_file`. They
  are recorded like them, marked as Kimi's own requests.
- Model names may now carry one provider prefix (`kimi-code/k3`). A model name is still never a
  command-line option or a file path.

## Install

Download `Plenipo_1.5.0_x64-setup.exe` below and run it. It is a per-user install with no admin
rights needed. The installer is not code-signed yet, so Windows SmartScreen may warn: choose
**More info → Run anyway**. This release adds nothing new to the Ledger (Plenipo's saved
record of all work).
