# v1.5.0 — Servers: workers on your servers over SSH (Phase 11)

Workers can now work on your Linux servers over SSH: check how a server is doing, read its logs,
restart a service, or deploy. They work only on the servers you set up, only with the kinds of
commands you allow, and never with your keys or passwords in their hands. On a production server,
every command waits for you.

It starts **switched off**. Turn it on in **Settings → Switches → Remote computers (SSH)** when
you are ready.

## Highlights

- **Settings → Servers.** Add each server with:
  - a name, its address and port, and the user Plenipo signs in as;
  - what it is: **Test**, **Staging**, or **Production**. Production is red and in capitals
    everywhere: the server's card, the approval card, the sign, and the tray. Staging is amber
    and Test green;
  - how Plenipo signs in: a private key (choose the file) or a password, both kept in Windows
    Credential Manager, or your own SSH agent;
  - which roles may use it, the kinds of commands it allows, its folders, when to ask you, and
    any ports it may forward.
- **Server IDs are pinned.** When you add a server, **Check the server ID** reads its
  fingerprint. Compare it with the one your hosting provider shows, then press **This is my
  server: pin this ID**. Plenipo checks it every time it connects, before it signs in. If it
  ever changes, the work is blocked, nothing is sent, and the server's card says **This server's
  ID changed**.
- **Keys and passwords stay yours.** They go from Settings straight into Windows Credential
  Manager and are never shown again: not to you, not to a worker, and not in the Activity trail.
  Workers pick a server by its name and never see a key or password. Your SSH agent is never
  forwarded to a server.
- **The kinds of commands.** A worker runs a program with its arguments, never a shell line, and
  Plenipo sorts each command into one of six kinds:
  - Look around
  - Start, stop, and restart services
  - Install, deploy, and change files
  - Delete, wipe, or shut down
  - Run as administrator
  - Other commands

  Each server allows only the kinds you tick. Commands that change things stay inside its
  folders. Reaching other computers from a server (ssh, scp, nc, …), scanning the network, and
  reading blocked files such as keys are never allowed.

- **Production waits for you.** Every command on a production server waits for your approval,
  even `uptime`. Any change there also counts as "Deploying or changing live systems", so
  setting that to **Blocked** in Settings → Permissions blocks every change on production.
  Deleting, wiping, or shutting down is off on production unless you turn it on, and then it
  still asks.
- **You see it, and you can stop it.** While a worker is connected, the sign on every page names
  it and the server, with **Disconnect**. **Stop all** (in the app and the Windows tray) covers
  servers too, and switching **Remote computers (SSH)** off disconnects every worker at once.
  Every connection, command, line of output (with secrets hidden), and approval is in the
  Activity trail.
- **A new role: Operations Engineer.** It looks before it changes anything, changes only what the
  task needs, reports what it ran and what it showed, and stops to ask when something is blocked
  or a server ID changed. It starts with the new
  **Servers** permission set.
- **Lessons from servers ask you.** What a server prints is outside information, like a website.
  A lesson from a task that used a server always waits for you, even for a role that learns on
  its own.

## Upgrading from 1.4.0

There is no Ledger change. On first start, Plenipo adds the **Servers** permission set and the
**Operations Engineer** role to the hire palette. **Remote computers (SSH)** is off, and no
existing role can connect to servers. Your permissions, switches, and approvals are unchanged.

## Risks, said plainly

- **Looking can read anything the user can.** Sign in as a user with only the access the work
  needs, not `root`. Blocked files (keys, `.env`) are refused by name, but a server can hold
  secrets anywhere.
- **Secrets in output are hidden only when Plenipo can recognize them:** your stored keys and
  passwords, and common formats (private keys, tokens, `PASSWORD=` settings). An unusual secret
  printed by a server may show in the Activity trail.
- **The first server ID is yours to check.** Plenipo trusts the ID you pin. Compare it with your
  hosting provider's before pinning.
- **A server can steer a worker.** What a server prints could contain words meant to mislead an
  AI worker. Workers are told that server output is information, never instructions, and every
  change asks you on production. Keep production's "every command" on, and read the cards.
- **Old servers may keep running a stopped command.** Stopping sends it TERM, then KILL, through
  SSH. Servers with OpenSSH older than 7.9 (2018) ignore those signals, so a stopped command may
  keep running even though the connection closes.
- **The kinds of commands are a careful list, not a guarantee.** A program Plenipo does not
  recognize is "Other commands", off by default. A recognized one can still do surprising things.

## Free and Pro

Servers are in the **Free** edition, like Plenipo's browser (your decision, recorded in
`docs/editions.md`). A ready-made Operations department, when one comes, would be Pro, like
Sales. No license check exists yet.

## Known limits

- **Linux and Unix servers only.** Windows servers are not supported yet.
- **No shell lines:** no pipes, `&&`, or redirects. Ask the worker to run steps one at a time.
- **No terminal for you, and no file copying (SFTP),** in this release. Use your own SSH program.
- **Not yet checked on Windows against a real server.** Verified end to end with stand-in AI
  tools and a synthetic SSH server on Linux. Your Windows check is in the
  [Phase 11 checklist](https://github.com/Seckcey/plenipo/blob/main/docs/phases/phase-11-checklist.md).

## Install

Download `Plenipo_1.5.0_x64-setup.exe` below and run it. It is a per-user install with no admin
rights needed. The installer is not code-signed yet, so Windows SmartScreen may warn: choose
**More info → Run anyway**.
