# v0.8.0 — Workers can use your computer, with your permission (Phase 7)

Workers in your organization can now read and change files, run programs, and use git — only
inside their project's folder, only as far as you allow, and never anything sensitive without
asking you first. Every use is checked, recorded, and can be stopped.

## Highlights

- **A folder per project.** Give a project its folder (when you create it, or **Edit project**).
  Its workers work only inside it; anything outside is blocked and shown to you.
- **Settings → Permissions.** Each role has a permission set — read files, change files, run
  programs, run PowerShell scripts, read git history, save to git — each **Allowed**, **Ask me**,
  or **Blocked**. The Senior Developer starts with **Developer**, reviewers with **Reviewer**,
  and so on; change them or make your own. A project or department can only narrow a role's
  permissions.
- **Programs you trust.** List the programs workers may run without asking (for example
  `npm test *`), the ones that always ask, and the ones that never run. Files such as `.env`
  and private keys can never be opened.
- **Your approval for anything sensitive.** Deploying, DNS changes, passwords and credentials,
  database wipes, deleting cloud resources, payments, publishing and `git push`, and running as
  administrator always stop for you. A banner appears on every page; the card on **Approvals**
  says exactly what will run and why. Approve, deny, or let it expire (10 minutes by default).
  You can make these stricter (blocked), never looser.
- **Revoke at any time.** **Approvals → Workers using permissions now → Revoke** stops a worker's
  running programs and refuses anything it asks for next.
- **Secrets stay secret.** **Settings → Permissions → Secrets** stores values in Windows
  Credential Manager, not in Plenipo's files. You choose which programs get a secret; workers
  never see the value, and secrets are hidden wherever they would appear.
- **Everything recorded.** Every file read or change, program run, block, and approval is in the
  Activity trail.

Also in this release: shorter messages between workers (ADR-012) and the groundwork for adding
more AI tools — Gemini, GitHub Copilot, and Grok are next (ADR-014).

## Install

Download `Plenipo_0.8.0_x64-setup.exe` below and run it. It is a per-user install with no admin
rights needed. The installer is not code-signed yet, so Windows SmartScreen may warn: choose
**More info → Run anyway**.

No Ledger upgrade is needed. After updating, give your projects a folder in **Edit project** so
their workers can work on files; until then they stay conversation only.

## Known limits

- **Codex can still read outside the folder.** Codex's own read-only commands can read (not
  change) files outside the project folder. Claude Code workers cannot.
- **Approved programs are trusted.** A program on your approved list, like `npm run build`, runs
  the project's own scripts without asking. Keep the list to commands you would run yourself.
- **Not yet checked with the real AI tools.** Phase 7 was verified end to end with stand-ins for
  Claude Code and Codex; the owner's check with the real ones on Windows (the Phase 7 checklist)
  is still to come, and anything it finds goes into a patch release.
- Workers you start from the **Workers** page stay conversation only; permissions apply to your
  organization's workers.
