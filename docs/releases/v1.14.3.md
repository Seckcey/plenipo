# v1.14.3 — WooCommerce keys: add one later, and see why one is refused

A fix to the website's connection from Phase 20, found by the owner on Windows. Plenipo by
**8 West Ventures, LLC**.

## Changes

- **Add a WooCommerce key after the site is connected.** The connected WordPress and WooCommerce
  card has its own **Add a WooCommerce key** section (**Replace the WooCommerce key** once one is
  kept), with only the key and its secret. Plenipo checks the key with the Application Password
  it already keeps, so that password is never typed again. Before, the only way was **Replace the
  key**, which asked for the Application Password again, and WordPress shows it only once.
- **A refused key says why.** Before, every refusal said "WooCommerce did not accept that key and
  secret". Now the card says which it is:
  - the key's WordPress user may not see the store's orders (an Editor's key): make that user a
    Shop Manager;
  - the secret does not match the key;
  - WooCommerce does not know the key (copied short, or revoked);
  - the key is Write only;
  - WooCommerce never saw the key, or a firewall stopped the request first.
- **The key steps were wrong** about the store: they said a WooCommerce key works for an Editor.
  A key can do only what its WordPress user may, so the store needs a **Shop Manager** either way.
  [Making keys for HubSpot, Stripe, and your website](https://github.com/Seckcey/plenipo/blob/main/docs/phases/phase-20-keys-for-hubspot-stripe-and-website.md),
  Part D, now says so, with what to do for each refusal.

Nothing else changed. This update does not change the Ledger.

Download `Plenipo_1.14.3_x64-setup.exe` below and run it, or let Plenipo install the update. It is
