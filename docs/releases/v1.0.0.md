# v1.0.0 — The Development department (Phase 8)

Plenipo's first full release. Tell Development what you want — "implement the login page in
Website and get it ready for review" — and it gets done by a team of AI workers on Claude Code
and Codex, without you opening either one. You get back one result that says exactly what was
done, recorded by Plenipo rather than claimed by the AI.

## Highlights

- **Set up Development in one step.** **Projects → Set up a Development project** creates the
  Development department with its VP (if you don't have one yet), the project with its
  Supervisor, and a team on call: a Senior Developer, a Code Reviewer, a QA Engineer, and a
  Documentation Writer. Each role's model choices pick its AI tool, so reviews can come from a
  different AI company than the code.
- **Give Development an objective.** Type it on the Projects page. The VP hands it to the
  project's Supervisor, who works in its own conversation and keeps its memory of the project.
  The Supervisor breaks the work into small tasks, has the developer implement and commit, the
  reviewer review, fixes what the review finds, has QA run the tests, and reports back.
- **Your own copy is never changed.** Each objective works on a new branch (`plenipo/…`) in its
  own working copy of your project folder, kept in Plenipo's data folder. Workers cannot switch
  branches or push anything but their own branch, and pushing still asks you. Merge the branch
  when you are happy with it; **Remove** the working copy when you are done — the branch stays.
- **GitHub.** With GitHub's `gh` program signed in (or a GitHub token under **Settings →
  Permissions → Secrets**), workers can read your project's pull requests, checks, and issues,
  and open a draft pull request for the objective's branch. Opening a pull request always waits
  for your approval.
- **The result.** For every objective, the Projects page shows what happened, live while it
  runs: every task and who did it, the AI tools and models used, the files changed (committed or
  not), the tests and programs run and whether they passed, the reviews and any open findings,
  the branch, its commits, and the pull request, approvals still waiting, and anything that
  needs your attention — next to the VP's own summary.
- **Room for review loops.** A task can now go back and forth 8 times (was 5), and an objective
  can hand out 16 tasks (was 12), so the team can review, fix, and test again.

## Upgrading from 0.8.0

Plenipo upgrades its Ledger on first start (schema version 6: working copies), after a verified
backup, as with earlier upgrades. Your projects get **Work on a separate branch for each
objective** turned on; it applies when the project folder is a git repository with at least one
commit. Turn it off in **Edit project** to let workers change the folder itself, as before.
Built-in permission sets you have not changed gain GitHub (reading for all four; the Developer
set can also open pull requests, which always asks you); sets you changed are left alone.

## Known limits

- **Not yet checked with the real AI tools.** Phase 8 was verified end to end with stand-ins for
  Claude Code, Codex, and GitHub's `gh`; the owner's check with the real ones on Windows (the
  Phase 8 checklist) is still to come, and anything it finds goes into a patch release.
- **Merging is yours.** Plenipo never merges a branch or a pull request. When two workers of
  one objective changed files at the same time, the second worked on `<branch>-2`, and the
  result tells you to merge it.
- **Working copies use disk space** until you remove them (Projects → Working copies).
- **Reviews depend on the reviewer's verdict block.** A reviewer that leaves it out shows no
  verdict in the result; its answer is still in the task.
- From Phase 7: Codex's own read-only commands can still read files outside the project folder,
  and approved programs are trusted to behave.

## Install

Download `Plenipo_1.0.0_x64-setup.exe` below and run it. It is a per-user install with no admin
rights needed. The installer is not code-signed yet, so Windows SmartScreen may warn: choose
**More info → Run anyway**.
