# v1.25.0 — Fixes, and a simpler Plenipo you can see and steer

**This release fixes what was broken, makes Plenipo simpler to set up, and lets you watch and stop
the work as it happens. AI plans last longer, made-up answers are caught, and leads can stop their
own team mid-task. Under Careful, build and test commands now ask first, and Guard checks files and
scripts more closely.** Plenipo by **8 West Ventures, LLC**.

## Fixed

- **A new organization no longer freezes Plenipo.**
- **Usage adds up every organization**, not only the first one.
- **One green light** on an AI tool's card when its subscription or its key works.
- **Save a paid key once for the whole PC.** Every organization uses it.
- **A page no longer shows old information right after a change.** An older answer that arrives
  last no longer replaces a newer one. A request you just answered no longer shows as waiting
  again, and a change you just made no longer flips back on screen. This covers Approvals,
  Activity, Projects, Learning, Servers, Settings → Permissions, Connections, AI models, and AI
  tools, the organization's map and chart, each department's, project's, worker's, and task's
  page, and the top bar's **Showing** picker.
- **The file editor shows when a worker is writing a file.** After you save, the editor checks
  again whether a worker is writing that file, so it no longer stays open for editing while a
  worker writes it. And it no longer goes back to read-only after the worker is done.

## Simpler

- **AI tool cards start closed**, with a light and one line each. A card that needs you starts
  open.
- **Fewer questions about models.** Plenipo no longer asks for a model's context size, or whether
  it makes images or uses a computer.
- **Who uses what** (Settings → AI models) picks the exact model for each job, on one screen.
- **The team you hired comes first.** A new project uses the workers you already have, and a
  manager asks before bringing in one you don't.
- **Templates** for organizations, departments, and projects, and you can save your own.
- **A nine-step setup tour**, from signing in to your first objective. **Take the setup tour
  again** is in Settings.

## See and steer the work

- **Watch a worker type its answer live**, with its steps in plain words ("Running `npm test`").
- **Watch shows what commands change.** Plenipo notes the files before a command and compares them
  after.
- **Stop on every worker.** Only that task stops, and its lead carries on.
- **Stop all work** is on every page that shows work. Nothing new starts until you press **Allow
  again**.
- **Ask a question** opens a side chat with a manager or supervisor. It only answers, and it never
  touches the work.
- **Leads can stop their team mid-task.** While their team works, supervisors, managers, and VPs
  get short check-ins: when an answer comes back while other work still goes, and after a long
  wait. They can stop work they handed on that no longer makes sense, with a reason. Activity and
  Handoffs show who stopped what and why ("Stopped by Website Supervisor: …"). Your own **Stop**
  and **Stop all** work as before.

## Plans that last

- **Prompt caching on Anthropic models.** The **Usage** tab shows what came from the cache.
- **When a plan runs out,** a notice gives you choices: **Wait**, **Use a reset**, **Pick it up
  now**, **Use another AI tool**, or **Leave stopped**. Unless you chose Leave stopped, the work
  starts again by itself after the reset.
- **Plan numbers in plain words.**
- **Your subscription first, then the same company's key.** This happens only when **Let workers
  use paid AI keys** is on, a key is saved, and there is room under your spending caps.
- **Step down instead of stopping.** Near your limit, a worker moves to a lower effort or a
  smaller model first. Its **Why** says so, and Activity records it.
- **A fair pace across the week and the month.** **Your plans** on the AI tools page shows each
  plan's pace.

## Made-up answers caught

- **Every answer is checked against Plenipo's own record** of files, tests, and pull requests. One
  that doesn't match shows "Doesn't match the record" and is sent back once to check.
- **Links and pull requests named in an answer are checked.** A link is looked at only when its
  website is on your allowed list.
- **Leads can send work back.**
- **A notice when a worker keeps failing.**

## Safer

- **Build and test commands ask first under Careful.** Commands such as `npm test`,
  `cargo build`, and `pytest` run code the project itself holds, so they are no longer on the
  **Approved** list Plenipo starts with.
  - On **Light** (where Plenipo starts), nothing changes. On **Strict**, workers still run no
    programs.
  - On **Careful**, each one shows an approval card every time. To stop that for a project you
    trust, add the command to **Approved** in **Settings → Permissions**.
  - A new install starts with four approved commands: `tsc`, `ruff`, `black`, and `gofmt`. An
    install from an earlier version loses the old starting lines once, word for word. Lines you
    wrote or changed stay, and Activity says what changed.
- **Web pages and SVG drawings open in Plenipo only.** **Open in another program** refuses `.html`,
  `.svg`, and similar files, because their scripts would run in your browser. It also refuses more
  kinds of script, such as `.ahk`, `.rb`, `.tcl`, `.r`, and `.jl`.
- **The git tools look only at the project folder**, even when it sits inside a larger repository.
  `git status` leaves blocked files, such as `.env`, out and says how many.
- **A file named by its full path** gets the same name checks as one named from the project folder.
- **A file is checked again at the moment it is opened.** On Windows, a file a worker reads or
  changes is opened without following a link put at its name at the last moment. A Mac and Linux
  already did this.
- **A hard-linked file is never changed by a worker.** A hard link is the same file in two places,
  which no folder check can see. The worker is told to copy it first. The packages pnpm installs in
  `node_modules` are hard links, so a worker can no longer change one of them in place.
- **The programs inside a PowerShell script follow your lists** under Light, as a command line
  does. A script that names a program on your **Never run** list is refused, with the line. One
  that names a program on your **Always ask me first** list, deletes or moves files outside the
  project folder, or has a line Plenipo cannot read shows an approval card that says which line and
  why. Ordinary scripts run as before. Under **Careful** and **Strict**, nothing changes: every
  script already asked, or none runs.
- **Guard reads commands inside shell text more closely, and stays allow-first.** Nothing new is
  refused for ordinary commands.
  - Asking whether a program is installed (`command -v rm`) is no longer refused, even when that
    program is on your **Never run** list.
  - A rule you write on a word such as `nohup`, `env`, or `time` now also catches it inside shell
    text, such as `bash -c "nohup make"`, as it already did on a plain command line.
  - The settings such a word takes before its program are read correctly. An option Guard does not
    know asks you, instead of guessing.
- **Stricter checks for hidden characters.** Text a worker types on your screen can no longer hold
  any invisible character, because you approve that text from a card and must see all of it. As
  before, this means joined emoji (such as the family emoji or the rainbow flag), the England,
  Scotland, and Wales flags, and the joiners that Persian and Urdu use between letters cannot be
  typed by a worker. Plain emoji still work.
- **An AI tool's update** records in Activity the exact command it ran.
- **A browser click you approved goes only where its card said.** Plenipo stays allow-first:
  ordinary clicks still never ask, and nothing changes for them. Only a click that already asked
  for your approval, such as one that sends a form, is now limited to where its card said. The card
  now says where the form sends, for example "sends to shop.test/send". If the page tries to send
  it somewhere else after you approve, or slides a different button under the pointer, Plenipo
  stops it. A page whose button sends to a website the card did not name shows one more card,
  naming that website.
- **Server updates are signed with their own key.** The relay and the phone's page now carry a
  signature made with a key of their own, separate from the app's, so 8 West's servers install
  only updates that 8 West Ventures, LLC made.

## For you, the owner

- Install this update on your PC. Plenipo offers it by itself (it checks GitHub once a day), or
  you can download it from this release.
- **On Careful, expect approval cards for build and test commands** until you add the ones you
  trust to **Approved**.
- **Each check-in costs one short step** on the lead's AI tool, at most four while one batch of
  work runs.
