# v0.5.0 — Liaison handoffs between workers (Phase 4)

Workers can now ask each other for help. Allow handoffs when you start a task, and a Codex
worker can ask Claude Code to review its work, or the other way round. Plenipo runs the reviewer
as a separate worker, brings its reply back, and the original worker continues with it. Every
step is recorded in the Ledger.

## Highlights

- **Handoffs between workers.** Tick **Allow handoffs to other workers** when you start a task
  in **Workers**. The worker can then hand part of the job, such as a review, to a worker on the
  other runtime through Plenipo Liaison. The task shows **Waiting for replies**, then continues
  in the same conversation, using the reply as its next step.
- **See every handoff.** Each handoff appears as a card showing where it went, its status, the
  context that was passed, and the reply. **Open worker session** shows the helper's own
  session.
- **Delegation tree.** **Activity** shows each workflow's tasks across workers, and a
  plain-language trail of every request, reply, and continuation.
- **Stay in control.** Cancelling a waiting task also stops the handoffs it is waiting for, all
  the way down. **Diagnostics** shows Liaison's limits, destinations, and open handoffs.

## Fixes

- Switching views now opens the new view at its top, instead of where the previous view was
  scrolled.

## Safety

- **Workers never control each other.** A worker can only ask. Plenipo checks every request
  against a strict format, records who sent it from its own records, and refuses anything else,
  including requests addressed to another worker's session.
- **No provider switching.** A request goes only to the runtime it names. If that runtime is
  not installed or not signed in, the handoff fails with the reason and the requester carries
  on.
- **Only what's needed is shared.** The helper receives the request and only the context the
  requester pointed to, capped in size. Files are passed by reference, never by content.
- **No new permissions.** Helpers run read-only like any other worker. Requests for extra
  capabilities are recorded and refused until Plenipo Guard (Phase 7).
- **Bounded.** Handoffs are off unless you allow them for a task. Limits: 3 levels deep, 3
  requests per answer, 5 reply rounds per task, 12 handoffs per workflow. Each handoff uses
  turns on your own subscriptions.

## Install

Download `Plenipo_0.5.0_x64-setup.exe` below and run it. It is a per-user install with no admin
rights needed. The installer is not code-signed yet, so Windows SmartScreen may warn: choose
**More info → Run anyway**.

Your existing Ledger is upgraded automatically (to schema version 3), after a verified backup of
the previous version in the Ledger's `backups` folder. After the upgrade, earlier versions of
Plenipo cannot open the Ledger.

Handoffs need both Claude Code and Codex installed and signed in (see the
[setup guide](https://github.com/Seckcey/plenipo/blob/main/docs/development/setup.md#3-agent-runtimes-phase-3-optional)).
